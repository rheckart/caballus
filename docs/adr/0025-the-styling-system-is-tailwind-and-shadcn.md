# The styling system is Tailwind and shadcn, and the horse record is where it starts

`src/styles/app.css` was 1961 lines of hand-written CSS over 260 top-level selectors, and `src/components/forms.tsx`'s own header argued for it: _"the screens were written as plain semantic HTML and the redesign kept that, because `src/styles/app.css` can carry an element."_ That argument was correct about **elements** and it was never an argument about **behaviour**, which is exactly what `forms.tsx` says next. The decision here is that behaviour is now bought rather than built, and that buying it means taking the styling system it comes with.

The trigger was `/admin/horses`, and it is worth recording what was actually wrong with it, because the fix is a rearrangement and a reader six months from now will assume it was a paint job. One open horse rendered **eight independent forms with eight save buttons** — Attributes, four Space assignments each with its own _Set_, Raise an alert, Publish, Mark Departed — in a `<section>` **below** the sixty-row table that opened it, so the record was off-screen on the desk it was opened from. Every refusal was rendered at the top of the page rather than beside the control that caused it, nine call sites deep, each carrying the comment _"Already at the top of the screen, put there by `act`."_ A save confirmation lived for 2500ms. The intended reader is a volunteer coordinator in their sixties who does not use software for a living, and every one of those four is the same failure to them: **I pressed the button and I cannot tell what happened.**

## The record is a modal of five tabs, and only one tab may be unsaved

The five are **About her**, **Location**, **Alerts**, **Feeding** and **She has left**, and each is one form with one Save. This retires the _Save all changes_ button that a first pass proposed: one button firing five writes has to explain a half-failure, and _"which of my five things saved?"_ is a worse question than _"why does this screen have five buttons?"_ A tab is roughly an endpoint, so a save is roughly a write. **Location** is the exception — four Space assignments behind one Save — and it saves them in order and stops at the first refusal, leaving the successful ones locked and the rest untouched rather than reporting one failure over the whole card.

**Switching tabs or closing the modal with unsaved typing stops and asks.** That is the rule the whole shape rests on: because only one tab can ever be dirty, there is no hidden unsaved state anywhere, and no save ever writes something the person cannot see. React Hook Form's `formState.isDirty` is what answers _dirty_, which is the one thing shadcn's Form contributes that `useSaving` does not already do. Nothing auto-saves; a person who has not pressed a button has not saved.

Two acts stay off the Save buttons entirely. **Departure** and **ending an Alert** confirm **inline, inside the card**, never in a second modal — a `<dialog>` inside a `<dialog>` makes Escape ambiguous, and _"I changed her halter colour"_ and _"she is gone"_ must not share a button.

## The `Photo URL` input is removed rather than redesigned

It was a `type="url"` text box with a 2000-character limit, on a desk whose reader cannot produce a URL. The column stays, the photo still renders where one exists, and the input is gone until object storage lands — the same gap #34 left the Release Version's blank template pointing at, and #35 left the horse photo in. A field nobody can fill is worse than an absent one, because it reads as a thing the person failed to do.

## Full migration, and the 72 custom properties are why it is affordable

`app.css` already carried **72 CSS custom properties**, which is a token layer under a different name. They become Tailwind v4's `@theme`, so the migration is a transcription rather than a re-palette. A coexistence plan — Tailwind on new work, `app.css` on the old screens, sharing the tokens — was considered and rejected on the grounds that nobody ever finishes that migration; the half state becomes the permanent state and the repo carries two systems forever. Full migration is more work and it ends.

The order is **install and prove on `/admin/contacts`** (351 lines, one screen, real forms), then **the horse record**, then the remaining screens with **`/board` last**. The Board is last because it is the one screen where a styling regression is visible to an entire barn simultaneously and its colour comes from a Product's kind rather than from taste (ADR 0022). Shipping the horse record before the other fourteen screens means temporary coexistence, which the paragraph above just argued against — the difference is that here it is a fortnight with a ticket attached, not a plan.

## Considered and rejected: keeping the native `<dialog>` and the native `<select>`

Both were argued for and both were overruled, and the reasons are recorded because they will be raised again.

`Sheet` was a real `<dialog>` driven by `showModal()`: the focus trap, the top layer, the backdrop, the inert page behind and Escape all came from the browser for zero bytes and zero dependencies, which is more than Radix's Dialog gets for roughly two thousand lines of JavaScript. Against that: `preventClose` has to be hand-built either way, and a component library with a hole in it where the most-used component should be is a library nobody reaches for. **Consistency won.**

The eleven native `<select>` elements gave a desktop reader the operating system's own dropdown — the one they have used for twenty years, with type-a-letter-to-jump — and on a phone the native picker. Radix's Select is a listbox: no `<select>` element, no change event, and `fireEvent.change(getByLabelText('County'), { target: { value } })` at `src/routes/admin/attendance.test.tsx:77` stops working. **Consistency won there too**, and the cost is paid in `src/test/setup-dom.ts` — four jsdom stubs (`hasPointerCapture`, `scrollIntoView`, `ResizeObserver`, `matchMedia`) — plus a `chooseOption(label, text)` helper in `src/test/route-harness.tsx` so that no test has to know what a dropdown is made of. Those land in the **first** ticket, not a later one: a red suite somebody is _getting to_ is a suite nobody trusts.

What is **not** taken from shadcn is its validation story. The zod contract in `src/shared/api-contract.ts` is the single source of what a payload may be (ADR 0021), and React Hook Form owns field state and dirtiness only. `useSaving` keeps the submit lifecycle — pending, the button that cannot be pressed twice, and the confirmation — because that is what makes the sticky _Saved_ and the dirty-tab rule work, and it is not what a form library does.

## Consequences

**Icons arrive, and never alone.** `lucide-react` comes with shadcn and the application had no icons at all — the sheet's close button was a literal `×`. An icon **beside** a word helps the intended reader; an icon **instead of** a word is the single most reliable way to make a sixty-year-old stop and stare at a screen. Icon plus word, everywhere, without exception.

**Dark mode ships with the migration, because the tokens are being rewritten once.** It is three named choices — System, Light, Dark — defaulting to System and remembered in `localStorage`, and it is deliberately not a two-state toggle: a switch reading _Light_ cannot tell you whether you chose that or the system did, and offers no way back to letting it decide. An inline script in `__root.tsx`'s `head` sets the class **before first paint**, because the application is server-rendered and the server does not know the choice; without it every load flashes the wrong theme, which is the class of defect that is noticed forever and diagnosed never. **`/board` is pinned light** regardless of both the system setting and the stored choice — the shell is already switched off there (`bare = ['/login', '/board']`) and a wall display must not go dark at dusk because a tablet's OS decided.

**Only the semantic tokens get a dark twin, and that is a decision rather than an oversight.** All 72 custom properties are light-only — `--canvas` is `#ffffff` and there has never been a dark value for anything — so "the 72 become the `@theme`" is a transcription in light and an invention in dark, which the first draft of this decision did not say. The invention is deliberately kept small: the dozen shadcn semantic tokens (`--background`, `--foreground`, `--card`, `--muted`, `--border`, `--ring` and the rest) get a dark value from shadcn's own defaults, and the brand colours and the nine pastel card tints keep a single value in both themes. The accepted cost is that a card tint used as a **fill** looks wrong on a dark background; the answer is to spend it as an accent — a border, an icon, a badge — rather than to design nine dark pastels nobody asked for. A full dark palette later is a change of values and no code.

The mapping is **by role and never by name**, because the two vocabularies collide in one place that matters: `--muted` in `app.css` is `#bbb8b1`, a **text** colour, and `--muted` in shadcn is a **background**. Mapping by name there produces something that looks nearly right, which is worse than something that looks broken.

**The screens stop speaking the glossary's words, and `CONTEXT.md` does not move.** _Attributes_ becomes **About her**, _Publish a version_ becomes **Change her feed**, _Valid from_ becomes **Starting on**, _Route_ becomes **How it's given**, and the row's _Open_ button becomes **Edit**. The model keeps _Feed Schedule_, _Departed_ and _Route_ exactly as `CONTEXT.md` defines them; the screen speaks the barn's English. That rule is written into `CONTEXT.md` itself so the next screen does not have to rediscover it.

**`DESIGN.md` goes stale on contact and is not rewritten up front.** It carries a note pointing here and is revised lazily as each screen migrates. Describing a system that does not exist yet is a day spent on fiction.

**Two things this deliberately does not do.** The open horse does **not** go into the URL — `?horse=<id>&tab=feeding` would be the first search-param use in the codebase and it is the only item in this design with no payoff for the person it was designed for; it is its own ticket. And the guardrails are untouched: `noInlineConfig` stays on, so any `eslint-disable` comment shadcn generates is stripped as it arrives rather than exempted, and the copied components in `src/components/ui/` are ordinary source the repo owns, lints and pins like everything else (ADR 0016).

## Amendment: the tab labels, and the modal is shared

Two of the five tab names change, and the modal itself becomes one implementation instead of one screen's.

**_About her_ becomes _Core Details_, and _She has left_ becomes _Departure_.** Both original labels read as barn English, which is what this ADR asked for, and both fail the moment a second record uses the same modal: a volunteer's record has an _About her_ tab about somebody who may not be a her, and _She has left_ is not what a Coordinator calls removing a person from the rescue. _Core Details_ and _Departure_ are the two words that survive being said about a horse and about a person, and they are still not glossary terms — the model keeps Attributes and Departed exactly as `CONTEXT.md` defines them. The rest of the mapping in "The screens stop speaking the glossary's words" stands unchanged.

**The modal moves to `src/components/record-modal.tsx`.** The dirty-tab rule, the _You have changes you haven't saved_ prompt, `useRecordForm`, the inline refusal and the sticky _Saved_ were the horse record's own code; the volunteer record is the second desk that wants exactly them, and the rule that **only one tab may ever be unsaved** is not a rule if there are two implementations of it that can drift. A tab's form now finds the modal through context rather than a threaded `register` prop, so a tab added later cannot forget to register and quietly opt out of the prompt.

**The volunteer record follows the horse record, including the row button.** `/admin/volunteers` was the last desk where the row said _Open_ and expanded a panel underneath the table; it is now **Edit** and a modal of four tabs — Core Details, Paperwork, Roles, Departure. The panel's single error banner at the top goes with it: every refusal now lands beside the button that was pressed, which is the same argument this ADR already made for the horse record.

**The screens stop saying _her_.** _Change her feed_ becomes **Change the feed**, _Mark her as departed_ becomes **Mark as departed**, _Keep her_ becomes **Keep the horse**, and the rest follow. The original copy read warmly because most of the rescue's horses are mares, and it is wrong on every gelding — a button that misgenders the animal in front of the volunteer is worse than a plain one. The same rule now covers the volunteer record, where the subject is a person and the cost of guessing is higher still.

## Amendment: a failed read is the tab's to show, and 401 is not 403

**A read the tab cannot do without shows its own failure.** `/horses/:horseId` feeds two tabs — Alerts and Feeding — and its refusal used to land in the page's own banner, which sits _behind_ an open dialog. What the reader saw was _Loading the schedule…_ that never resolved, on every horse, with no way to tell a dead session from a slow one. Both tabs now render the refusal in place with a **Try again**, and the page banner keeps only what the page itself failed at.

**And `refusalText` splits 401 from 403.** `src/server/api/authorization.ts` has always answered 401 for _nobody is signed in_ and 403 for _this person may not_, and both arrived at the phone as `not_authorized` — so a volunteer whose session had ended was told they did not hold a Domain Scope they in fact hold, and sent to a Coordinator who could not help. A 401 now says so and names the sign-in screen.

## Amendment: retiring one Shift Type's feeding

**Retiring a Feed Schedule is publishing a version with no lines, and it is now a button.** The act already existed — `publishFeedSchedule` takes an empty `lines`, and the profile reads it back as _No feeding at this Shift Type_ — but the only way to reach it was to set every row of _Change the feed_ to None, which the form explained in a sentence under the last row that nobody read. Each schedule card now carries **Retire this feeding**, confirming inline inside the card on the Departure tab's own precedent: _stop feeding this horse in the morning_ must not share a button with an amount being corrected. It takes a date, and says to backdate it when what is being retired is a schedule that should never have been published.

**No `retired_at` column, deliberately.** ADR 0003's catalogue tier marks retirement with a column — `products.retired_on`, `spaces.retired_on` (#64) — and the versioned tier does not need one: a version with no lines already says it, `materializeDay` already generates nothing from it, and a second spelling would be two facts about what a horse eats that are free to disagree. The retired Shift Type **keeps its card**, marked, rather than vanishing — a deliberate none and a question nobody has answered are different facts, which is the same three-valued distinction #38 draws for a Threshold and #41 for a Task Assignment.
