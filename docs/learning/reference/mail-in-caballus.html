Mail in Caballus

Every knob, every refusal, every connection URL. Designed to print.

Environment

Variable Unset means Read by
SMTP_URL No transport. Every send refuses; nobody can sign in. src/server/email.ts
EMAIL_FROM Empty From. Most real servers reject this. src/server/email.ts
BETTER_AUTH_SECRET Throws at startup. Deliberate — a default would sign everyone out later. src/server/auth/auth.ts
APP_URL Falls back to http://localhost:3000. src/server/auth/auth.ts

Connection URLs

# Local (Mailpit). Plaintext on the loopback, no credentials.
SMTP_URL=smtp://localhost:1025

# Fastmail — the POC sender (ADR 0009).
# Port 465 is TLS from the first byte, so smtps://.
# The username is an email address, so its @ must be written %40.
# The password is an APP PASSWORD; the account password will not authenticate.
SMTP_URL=smtps://you%40heckart.me:APP-PASSWORD@smtp.fastmail.com:465

# Resend — the go-live exit (ADR 0009).
# The username is the literal string "resend". The password is an API key.
# A verified domain is required before anything sends at all.
SMTP_URL=smtps://resend:re_YOUR_API_KEY@smtp.resend.com:465
Percent-encoding

Anything in the credentials half of the URL that is also URL syntax must be encoded: @ → %40, : → %3A, / → %2F, # → %23. A Fastmail app password is generated from a safe alphabet, but the username always contains an @.

smtps:// means TLS from the first byte (port 465). smtp:// on port 587 starts plaintext and upgrades via STARTTLS. [Nodemailer]

The five refusals

requestCode and submitCode return a discriminated result. Every one of these is shown to the volunteer in plain words — ADR 0008 chose that deliberately over the usual "if that address is registered…".

Refusal Means Fix
unrecognised-email No live Volunteer at that address in this org Create one, or npm run bootstrap
volunteer-removed A Volunteer row exists but has removed_at set Re-create them; removal is a date, not a delete
account-revoked An officer switched the Account off restoreAccount
too-many-codes Three requests for that address inside an hour Wait, or restart the process — the window is in memory
email-not-sent No transport, the cap is spent, or SMTP rejected it Check SMTP_URL first, then the log line
wrong-code Wrong, expired, or already spent (5 attempts) Ask for a new one

Numbers

Thing Value Set in
Code length 6 digits CODE_LENGTH
Code lifetime 5 minutes CODE_EXPIRES_IN_SECONDS
Guesses allowed 5 CODE_ALLOWED_ATTEMPTS
Codes per address 3 per hour CODES_PER_ADDRESS
Messages per process 200 per rolling 24h DAILY_CAP
Session lifetime 365 days A_YEAR_IN_SECONDS
Cookie ceiling 400 days (not ours) RFC 6265bis

Log lines to grep

email_sent          # subject + redacted address. Never the code.
sign_in_refused     # carries stage (request_code | submit_code) and because
signed_in           # volunteerId + orgId
account_revocation  # outcome + how many sessions were ended
account_restored

The address is redacted by src/shared/scrub.ts on the way out, so "did we mail Grace" is not answerable from the log alone — only "how much did this process send, and of what". That is the trade ADR 0007 chose.

Local recipes

# Start Postgres and Mailpit
docker compose up -d

# The web inbox
xdg-open http://localhost:8025

# Latest subject (the code lives here)
curl -s 'http://localhost:8025/api/v1/messages?limit=1' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["messages"][0]["Subject"])'

# Empty the inbox
curl -s -X DELETE http://localhost:8025/api/v1/messages

# Tests need no SMTP at all — they swap the transport
npx vitest run src/server/auth/sign-in.test.ts
In tests, not in dev

setEmailTransport(fn) replaces the transport in-process and setEmailTransport(null) is the kill switch. The integration tests use it to read the code straight out of the message. It is not the dev-box lever — SMTP_URL is.
