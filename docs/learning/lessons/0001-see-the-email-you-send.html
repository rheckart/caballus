Lesson 1 · Email as Caballus' credential channel

See the email you send

Signing in on your own machine, start to finish, without a single message leaving it.

Caballus has one credential and it arrives by email (ADR 0009). That makes your dev box unusual: until mail works locally, you cannot sign in, and you cannot exercise a single line of the app that sits behind a session. The fix is a real SMTP server that catches everything instead of delivering it.

Why not just print the code to the console? Because a six-digit credential in a log is a credential in a log — and because a console transport skips SMTP entirely, which is the half most likely to be misconfigured when you point this at Fastmail.

What you already have

docker-compose.yml now runs Mailpit beside Postgres. It speaks real SMTP on 1025 and shows what it caught at localhost:8025. Nothing it receives is ever delivered. 

mailpit:
  image: axllent/mailpit:v1.28
  ports:
    - '1025:1025'   # SMTP — what SMTP_URL points at
    - '8025:8025'   # the web inbox
  environment:
    MP_SMTP_AUTH_ACCEPT_ANY: 1
    MP_SMTP_AUTH_ALLOW_INSECURE: 1

Those two variables matter more than they look. Without them Mailpit refuses unauthenticated plaintext connections, and you get a sign-in that fails for a reason that has nothing to do with your code. [Mailpit docs]

Do it

  1. Start both containers

    docker compose up -d

    Postgres was already there; Mailpit is the new one. Check it is healthy with docker compose ps.

  2. Point the app at it

    In .env:

    SMTP_URL=smtp://localhost:1025

    smtp://, not smtps:// — Mailpit is plaintext on the loopback. Leaving SMTP_URL empty is the state you were in before this lesson: there is no transport at all, and requestCode answers { sent: false, because: 'email-not-sent' } rather than pretending.

  3. Make sure you exist

    npm run bootstrap -- "Front Barn Horse Rescue" \
  America/New_York "Rob Heckart" rob@heckart.me

    A code is only ever sent to an address that already has a Volunteer (ADR 0008). No row, no code — you will get unrecognised-email, which is the app working correctly.

  4. Sign in

    npm run dev

    Open /login, enter your address, then read the code off localhost:8025. It is in the subject line, so you do not have to open the message.

The trap that will cost you an hour

You cannot read the code out of the database. Caballus sets storeOTP: 'hashed' in src/server/auth/auth.ts, so the verification table holds a digest and a colon and an attempt count — never the six digits. If Mailpit did not catch it, the code is gone. Look at the inbox, not at Postgres.

Who sends what

This is the part worth carrying into production, because it is where Caballus deliberately parts company with the library.

Step Owner Where
Is this address allowed a code? Caballus gate() in sign-in.ts
Mint the code, hash it, store it Better Auth api.createVerificationOTP
Send the message Caballus sendEmail in email.ts
Check the code, make a session Better Auth api.signInEmailOTP
Join the session to a Volunteer Caballus claimAccount

Row three is the surprising one. The plugin has a sendVerificationOTP callback built for exactly that job, and Caballus does not sign in through it. The Better Auth docs say why, in a line that reads as advice and behaves as a constraint: "It is recommended to not await the email sending to avoid timing attacks." [Better Auth docs]

A send that is not awaited is a send whose failure nobody hears. The volunteer was told { sent: true } for a message that never left — and with email the only channel there is, that is somebody standing in a barn waiting for a code that was never coming. So requestCode mints the code through Better Auth and then sends it itself, where a rejection is a value it can return.

Check yourself

Mailpit is running, but a sign-in answers email-not-sent. What do you check first?

An unset SMTP_URL means no transport at all, and sendEmail refuses rather than pretending. The other three produce different refusals: a missing row is unrecognised-email, and both an expired code and a casing problem would appear later or not at all.

You need the six digits and Mailpit was not running when the code was requested. Where are they?

storeOTP: 'hashed' means the table holds a digest, and sendEmail logs the subject and a redacted address but never the body. Ask for a new code — you get three an hour per address.

Why does Caballus send the code itself instead of letting the plugin do it?

The plugin's callback is not awaited in a way the caller can observe, so a rejection becomes sent: true. The cap point is a real consequence but not the reason, and the gate runs first either way.

Where this goes next

The same SMTP_URL lever points at production. Fastmail for the POC, Resend at go-live (ADR 0009) — and the connection URL is where the first real trap lives, because a Fastmail username is an email address and an @ inside a URL's credentials has to be written %40. That is Lesson 2.

Keep the mail reference sheet to hand. It has every refusal, every environment variable, and the connection URLs for all three providers on one page.
